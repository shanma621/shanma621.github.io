Rental Demand Analysis & Automated Genre Reporting

A PostgreSQL reporting workflow that analyzes movie rental demand by store location and genre using relational joins, transformation functions, summary tables, triggers, and stored procedures.

Read the Summary View Report View Code

Overview

This project analyzes movie rental demand by store location and genre using PostgreSQL. The workflow was designed to simulate a lightweight business intelligence reporting pipeline that supports recurring operational reporting and inventory planning.

What I Did

  • Joined rental, inventory, film, and category tables to create a detailed reporting dataset
  • Created PL/pgSQL functions to extract rental month and year from timestamp data
  • Built detail and summary reporting tables for genre demand analysis
  • Used a trigger to refresh summary metrics when new detail records are inserted
  • Created a stored procedure to rebuild the reporting workflow for recurring use
  • Documented the business purpose behind the technical design

Tools & Skills

  • PostgreSQL and SQL
  • PL/pgSQL functions, triggers, and stored procedures
  • Relational joins and aggregation
  • Detail and summary reporting table design
  • Operational reporting workflow development

Note: the full SQL script and project documentation are available in the GitHub repository.

Approach

Reporting Pipeline

  • Extracted transaction-level rental records from the database
  • Joined rental activity to inventory, film, and genre/category data
  • Transformed rental timestamps into month and year fields for reporting
  • Created a detailed reporting table for drill-down analysis
  • Created a summary table showing rental counts by store and genre
  • Added automation logic so summary reporting can refresh without manual rebuilding

Why This Matters

Store-level demand patterns can vary by location. Tracking rental demand by genre and store can help businesses stock inventory more strategically instead of guessing and hoping the spreadsheet goblins are feeling generous.

Example Query

SELECT
    store_id,
    genre,
    COUNT(*) AS rental_count
FROM rental_genre_detail
GROUP BY store_id, genre
ORDER BY store_id, rental_count DESC;

Results & Takeaways

What the Project Shows

  • Genre demand can be summarized by store location using relational database reporting
  • Detail and summary tables support both analysis and business-facing reporting
  • Triggers and stored procedures can reduce manual report maintenance
  • The same structure could be adapted for sales, inventory, customer, or operations reporting

What I’d Do Next

  • Add a Tableau or Power BI dashboard for interactive filtering
  • Include monthly trend visuals to show demand changes over time
  • Add indexes and performance testing for larger datasets
  • Extend the workflow to support inventory forecasting
  • Schedule recurring execution with PGAgent
